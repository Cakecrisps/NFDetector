Пакеты и протоколы¶

Серверный parser (dpkt) принимает PCAP и ограниченный PCAPNG: одна секция, один интерфейс, Enhanced Packet Blocks. Поддержаны Ethernet/VLAN, raw IP, Linux SLL/SLL2, IPv4/IPv6. Усечённые кадры, IPv6-фрагментация и некоторые PCAPNG layouts приводят к ошибке файла. Файл сначала разбирается в список и сортируется в RAM: лимит 500 000 кадров не равен гарантии малого RSS. JSONL с hex-payload может быть существенно больше PCAP.

IPv4-фрагменты и TCP-сегменты собираются между файлами. Прикладной decoder ограничен HTTP/1.x, HTTP Basic, FTP, TELNET, SMB/SMB2 Session Setup и SSH banners. TLS, HTTP/2, QUIC и зашифрованная SSH-аутентификация не анализируются на уровне содержимого. Байты до начала захвата восстановить нельзя.

Ошибки reassembly/прикладных сообщений дают DECODE_WARNING, очищают состояние затронутого flow и сохраняют L3/L4-анализ. Это не подтверждение атаки. Статистика протоколов отражает классификацию parser на уровне транспорта, а не полный L7-разбор TShark; прочие категории попадают в OTHER.

Качество детектирования¶

SSH greeting rate — возможный перебор, не число ошибок пароля. Пороговый DDoS может совпасть с легитимным всплеском. C2 считает интервалы пакетов пары IP, а не доказанные новые соединения с управляющим сервером. Для подтверждения нужны журналы сервисов, контекст нагрузки и исходный PCAP.

При capture loss, односторонней видимости, NAT, offloading или рассинхронизации часов полнота анализа ограничена качеством входа. Heartbeat не содержит достоверного счётчика потерь dumpcap; зелёный статус не доказывает полноту захвата.

При заполнении spool агент останавливает захват, сохраняя неподтверждённые файлы. Новые пакеты в период остановки не наблюдаются. Первый запуск capture требует соединения с сервером для регистрации потока; автономного старта нет.
