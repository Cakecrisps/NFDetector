Проверка репозитория 25 октября 2026¶

Объект: локальная ветка dev, база 960187f, после слияния agent-installer. Проверка основана на коде, конфигурации, автоматических тестах и локальной сборке. Она не является заключением о безопасности всей сети или гарантией производительности production.

Результаты и найденные расхождения¶

Область Вывод
Состав ветки Автоустановщик объединён с инцидентами, графиками и темами
Серверная схема Один TLS LB, внутренние API/БД/workers, общий data-volume; проверено чтением Compose/NGINX
Границы файлов Состояние сохраняет reducer домена; parser не изолирует историю атаки
Статистика Карточки/график/протоколы используют единый период и DB snapshot; capture-time инцидентов отличается от receipt-time файлов
SSH Greeting rate маркирован как возможный перебор; зашифрованные ошибки пароля не видны
Хранение Retention и GC отсутствуют, квота учитывает обработанные PCAP
Уведомления Сервер пишет outbox, но внешнего доставщика нет
Документация Старый pydoctor обошёл корень, включая .git, кеши и out; новый build использует явные Python roots
Smoke-test Проверка старых отдельных reasons несовместима с объединённым DDOS; исправлена на анализ kinds инцидента

Старый README обещал произвольные SIEM URL и неточно описывал пороги и защищаемые адреса. Архитектурный проект представлял часть будущих возможностей как готовые, а heartbeat ошибочно оставался среди планов. Описания заменены сверенными руководствами, статусом и отдельным планом.

Выполненные проверки¶

После объединения веток и повторно после обновления smoke-test: 142 теста прошли на Python 3.12 и отдельном PostgreSQL 16, без пропусков. Присутствовало одно предупреждение зависимости Starlette/httpx. Compose прошёл config --quiet, объединённые app.js и theme.js проверены парсером установленного Chrome.

Дополнительно выполнены:

  • Изолированный Compose HTTPS smoke-test: 150 004 синтетических пакета, два разных parser, второй файл завершён раньше первого; обнаружены DDoS_SINGLE_IP, HTTP_FLOOD, BRUTEFORCE_HTTP Basic. После объединения получилось два инцидента, DDoS и HTTP flood входят в общий DDOS. Сертификат проверялся через отдельный тестовый CA-файл.
  • Повторный микробенчмарк 500/1000/2000 событий, медиана трёх запусков: на 2000 событиях 3.76893 с против 0.00785 с для потокового ядра. Это не замер пропускной способности полного сервиса.
  • MkDocs strict + pydoctor warnings-as-errors: 84 HTML-страницы, все локальные ссылки и anchors проверены. Старые страницы .git, кешей и out отсутствуют. HTML полностью сгенерирован заново.
  • Chrome: все 19 страниц руководства, переход в API, английский и русский поиск, сохранение тёмной темы, мобильное меню при ширине 390 px. Нет ошибок JavaScript, HTTP-ошибок и внешних запросов ресурсов.
  • Исправлены русские slug/якоря, отключён CDN highlight.js; для темы без него добавлен небольшой исходный override генератора. Результат проверен визуально на настольном и мобильном экране.
  • Исправлена подсказка --protected_ips локальной CLI: это защищаемые цели, а не исключения. Новые PCAP, отчёты и окружение документации исключены из Git.

Автоустановщик проверен интеграционными тестами кода выдачи/обмена и артефактов. Повторная установка службы на реальной виртуалке в этом сеансе не выполнялась.

Границы этой проверки¶

Рабочие контейнеры в начале проверки были остановлены. Рабочая установка, агенты на виртуалках, правила и данные не изменялись. Предыдущие успешные ручные проверки не выдаются здесь за новый live-прогон.

Новый длительный нагрузочный прогон с реальным capture, потери dumpcap, заполнение диска, отказ Docker-хоста, восстановление резервной копии, ротация production-сертификата и точность правил на полном корпусе атак в этой проверке не подтверждены. Это задачи из плана.
