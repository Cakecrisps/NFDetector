# Как обновлять документацию

## Источник и результат

`README.md` — краткая точка входа репозитория. Все руководства редактируются
в `docs/`; меню находится в `mkdocs.yml`. `requirements-docs.txt` фиксирует
версии MkDocs и pydoctor. API-страницы строятся из docstrings Python.

`documentation/` — только сгенерированный результат. Не правьте отдельные
HTML: они будут заменены следующей сборкой. Старые страницы для `.git`,
кешей и логов удалены при полной регенерации.

```bash
python3 -m venv .venv-docs
.venv-docs/bin/python -m pip install -r requirements-docs.txt
.venv-docs/bin/python scripts/build_docs.py
python3 -m http.server 8080 --directory documentation --bind 127.0.0.1
```

Скрипт работает из любой текущей директории. Он собирает руководство и API
во временную папку внутри репозитория, проверяет ссылки и только после
успеха заменяет `documentation/`. Ошибка генератора не удаляет прежний HTML.
Окружения, БД, Docker, TShark и импорт приложения для сборки не нужны:
pydoctor статически анализирует явные источники `distributed`, `general`,
`nfdetect.py`. Вся директория проекта в pydoctor никогда не передаётся. Для ссылок на
стандартные типы используется локальная копия официального Sphinx inventory
Python 3.12 в `scripts/vendor/`; происхождение записано в `SOURCES.txt`.

В HTML включены русская навигация, поиск и выбор темы. Внешних CDN-загрузок
для оформления/скриптов нет. `use_directory_urls: false` позволяет
переходить по обычным `.html` файлам; для работы поиска надёжнее использовать
локальный HTTP-сервер. Все assets находятся в каталоге результата.

В `scripts/docs_theme/` находится небольшой override переключателя темы:
стандартный скрипт MkDocs 1.6.1 обращается к элементам отключённого CDN
highlight.js. Override поддерживает темы без этих элементов и переживает
недоступность localStorage. Это исходник темы генератора, не ручная правка HTML.

## Правила сопровождения

1. Изменили поведение — обновите соответствующее руководство, статус и тесты.
2. Проектные идеи пишите в плане с критерием готовности, а не как инструкции
   к уже существующей функции.
3. Добавили страницу — включите её в `nav` и проверьте относительные ссылки.
4. Изменили docstrings — пересоберите API вместе с руководством.
5. Выполните единую команду сборки, просмотрите результат и приложите diff.

Документация описывает версию исходников. Она не должна обещать, что конкретная
установка уже обновлена или что ранее выполненный тест повторён сейчас.
Текущий отчёт проверки обновляется явным результатом проверки, не автоматически.

## Разделы

- `getting-started/`: сервер, агент, локальный анализ.
- `guides/`: панель, конфигурация, инциденты, эксплуатация и диагностика.
- `architecture/`: текущий поток данных, API и ограничения.
- `project/`: состояние, оценка и план, результаты проверки.
- `development/`: тесты, производительность, сборка и API-справочник.
