# Настройки и детекторы

## Защищаемые адреса

`ext/protectips.txt` содержит **IP целей**, для которых включены пороговые правила.
Это не whitelist и не список исключений. Адрес должен совпадать с назначением
в PCAP после NAT в точке наблюдения. Создание агента не добавляет его IP в список.
Один адрес на строку; комментарии начинаются с `#`.

```text
192.0.2.10 # защищаемый сервер
2001:db8::10
```

`ext/suspips.txt` — независимый список подозрительных адресов для правил
`SUSPICIOUS_SOURCE_IP` / `SUSPICIOUS_DEST_IP`. Это не источник актуальной
репутации IP; поставляемые примеры не следует считать проверенным blacklist.

## Правила rules.json

Приведены значения из текущего файла, а не обещанная точность детектора.
Пороговые окна включают события на левой границе; срабатывание возникает
при достижении порога, не только при превышении.

| Правило | Параметры по умолчанию | Что считает |
| --- | --- | --- |
| DDoS, один источник | `ddos.1ip`: 1000 за 1 с | Пакеты source → защищаемая цель |
| DDoS, несколько источников | `ddos.nip`: 5000 за 2 с, `display_ips=10` | Пакеты к цели при наличии минимум двух источников |
| SYN flood | `flood.SYN`: 50 за 5 с | Ожидающие SYN-соединения source → цель; повтор SYN не увеличивает число, SYN-ACK снимает ожидание |
| HTTP flood | `flood.HTTP`: 80 за 1 с | Распознанные открытые HTTP-запросы source → цель |
| Brute force | `brute_force`: 10 за 20 с | Распознанные сообщения аутентификации; результат входа не подтверждается |
| SSH greeting rate | `brute_force.ssh_handshakes`: включён, `ports=[22]` | Клиентские SSH-приветствия разных соединений; наследует 10/20 с |
| C2 | `C2_analysys.beaconing_detection`: 10–300 с, jitter 5 с, минимум 5 | Регулярность пакетов пары IP; эвристика |

Названия `tryes_limit`, `tryes_limit_window`, `C2_analysys` исторические,
в JSON сохраняется именно такое написание. `warn_tryes_limit_window`
присутствует в конфигурации, но потоковое ядро не реализует отдельную тревогу
«массового перебора» на его основе.

`auth_proto` в поставляемом файле: `SMB`, `SMB2`, `SSH`, `FTP`, `TELNET`.
Для HTTP Basic добавьте строку `HTTP Basic` явно. Для SSH также нужны
`brute_force.enabled=true`, `SSH` в `auth_proto` и включённый `ssh_handshakes`.
В `ssh_handshakes` можно переопределить `limit`, `window`, `ports`, `enabled`.
Приветствие сервера и TCP retransmission не увеличивают число клиентских приветствий.

Для отключения группы используйте её `enabled: false`. `reaction.out`
относится к [локальному монитору](../getting-started/local.md); сервер
сохраняет outbox и сам внешние уведомления не отправляет.

После изменения правил, списков защищаемых или подозрительных IP действующий
checkpoint не продолжится под новой конфигурацией. Используйте отдельный
replay-домен либо подготовленную миграцию; универсальной команды миграции нет.

## Переменные окружения

| Переменная | По умолчанию | Область и назначение |
| --- | --- | --- |
| `POSTGRES_PASSWORD` | Обязательна в Compose | Случайный пароль БД, `.env` с правами 0600 |
| `NF_BIND`, `NF_PORT` | `0.0.0.0`, `443` | Опубликованный HTTPS-порт LB |
| `NF_TLS_HOST` | `localhost` | Имя в тестовом самоподписанном сертификате |
| `NF_TLS_CERT`, `NF_TLS_KEY` | — | Host-пути сертификата и ключа для `compose.tls.yaml` |
| `NF_PUBLIC_URL` | Пусто | Точный HTTPS origin панели; обязателен для удалённой первоначальной настройки |
| `NF_AGENT_URL` | Пусто | Подсказка адреса панели со стороны агента; не заменяет Origin панели |
| `NF_INCIDENT_GAP_SECONDS` | `300` | Максимальная пауза capture-времени внутри инцидента |
| `DATABASE_URL` | Задан Compose | Подключение API/workers к PostgreSQL |
| `NF_DATA_DIR` | `/data` | PCAP, артефакты, первоначальный setup-код |
| `NF_RULES`, `NF_PROTECTED_IPS` | `rules.json`, `ext/protectips.txt` | Пути внутри процесса; Compose задаёт абсолютные пути `/app/...` |
| `NF_MAX_UPLOAD` | `33554432` | Предел одного PCAP, байты |
| `NF_MAX_BACKLOG` | `2147483648` | Все сохранённые PCAP агента, не только необработанная очередь |
| `NF_MAX_STREAMS` | `16` | Число незакрытых потоков одного агента |
| `NF_BATCH_SIZE` | `2000` | Пакетов в транзакционном batch reducer |
| `NF_LEASE_SECONDS` | `60` | Срок владения заданием с продлением heartbeat |
| `NF_TRUST_PROXY_HEADERS` | `0`, в Compose `1` | Доверять только заголовкам закрытого API за своим LB |
| `NF_TLS_PUBLIC_CERT` | `/run/nf-tls/server.crt` | Публичный сертификат для bootstrap pin |

`NF_MAX_*`, batch, lease и некоторые другие параметры читает Python-процесс,
но Compose **не прокидывает их автоматически из `.env`**. Добавляйте их через
Compose override в `environment` нужных сервисов. Изменение серверного лимита
upload также требует согласовать `client_max_body_size` NGINX.
Checkpoint 64 MiB, 500 000 кадров/PCAP и 256 MiB/артефакт заданы в коде,
отдельных env-переменных для них нет.

```yaml
# compose.limits.yaml: пример явной передачи параметра в API
services:
  api:
    environment:
      NF_MAX_BACKLOG: '4294967296'
```

Повышение квоты только откладывает заполнение диска. Автоматическую очистку
оно не включает. Объём parser-артефактов и БД в эту квоту не входит.
