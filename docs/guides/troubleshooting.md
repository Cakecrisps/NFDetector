# Диагностика

Проверяйте конвейер по порядку: **захват → доставка → parser → reducer → правила → инцидент**.
Статус «агент на связи» подтверждает только запросы к серверу.

| Симптом | Что проверить | Что означает |
| --- | --- | --- |
| Нет файлов от агента | `systemctl status nfagent`, journal, интерфейс, TLS, IP панели со стороны агента | Захват/доставка могли не стартовать |
| Файлы приходят, событий нет | IP назначения в `ext/protectips.txt`, пороги, `auth_proto`, поддержка протокола | Не всякое подключение является срабатыванием |
| SSH не определяется | Клиентские banners, порт в `ssh_handshakes.ports`, 10 разных приветствий/20 с по умолчанию | Шифрованные password failures не видны |
| Файлы pending/parsing | Живы ли parser workers, ошибки и lease, доступ к volume | HTTP ACK подтверждает сохранение, не окончание анализа |
| Файл error | Ошибка parser: PCAP layout, усечённый кадр, лимит кадров | Файл не пропускается молча; домен ждёт его |
| Все файлы ready, анализ стоит | Незакрытый stream, пропущенный sequence, медленный источник, ошибка домена | Watermark консервативно ждёт все потоки |
| `Rules changed` | Меняли rules/защищаемые/подозрительные адреса | Нужен replay-домен или подготовленная миграция |
| Обратное время / late event | Часы, порядок загрузки, пересечение времён соседних файлов | Новая история не может быть вставлена ниже watermark |
| `429` на upload | Retained PCAP quota агента и rate limit LB | Квота включает уже обработанные файлы |
| `413` | Размер PCAP, лимиты API и LB | Уменьшите ротацию, не режьте PCAP произвольными байтами |
| `401` | Отозванный/заменённый ключ, использованный install-код | Повторите выдачу правильного вида credential |
| Не работает install-команда | Срок 15 минут, доступность публичного сертификата API, смена pin/пакета | Получите новую команду в панели |
| `502` после пересоздания API | IP upstream в работающем NGINX | Выполните `nginx -s reload` в LB |
| Нет удалённого первого входа | `NF_PUBLIC_URL`, точное имя/порт, setup-код | Origin и первоначальная настройка ограничены сервером |

## Где смотреть данные

```bash
docker compose ps
docker compose logs --tail=100 parser-worker detector-worker api lb
```

С агентским ключом `GET /v1/streams/{id}/status` показывает sequence,
статусы файлов, parser-владельцев, processed_sequence и ошибку домена.
Не вставляйте ключ в URL или публикуемые команды/логи. В панели используйте
«Агенты → Подробнее», «Трафик → Домены наблюдения» и детали инцидента.

## Почему график и время атаки различаются

График показывает приём PCAP сервером. Старый PCAP, загруженный сегодня,
войдёт в сегодняшний объём. Инцидент фильтруется по активности внутри захвата.
Текущее состояние агентов не является историческим срезом. Подробности —
в [описании панели](panel.md).

«Нет свежих данных» не доказывает завершение атаки. Если capture-время не
продвигается, reducer не закрывает инцидент только по серверным часам.

## Подтверждение работоспособности

Используйте отдельный тестовый домен с синтетическим PCAP из smoke-test,
ожидаемыми порогами и защищаемым адресом. Затем проверяйте конкретные
полученные инциденты. Успешный `/health`, открытая панель и работающий процесс
агента по отдельности не подтверждают полный путь обнаружения.
См. [проверки и smoke-test](../development/testing.md).
